# <Nombre de la feature> — UI

Capacidades que debe tener la UI, sin estilos ni componentes concretos: como si fuera HTML sin CSS. Reglas de negocio en `product.md`; aquí se referencian, no se repiten.

Las capacidades (qué muestra, qué permite, estados) son obligatorias. La forma (diálogo, página, ruta, posición) es una propuesta: si el diseño la resuelve distinto, se actualiza este archivo para reflejar lo construido.

## Pantallas nuevas

### <Pantalla>

- **Ubicación:** app, ruta o lugar, y desde dónde se llega (acción, botón, link).
- **Muestra:** qué datos se ven, con un ejemplo realista para trabajar con datos falsos.
- **Permite:** qué puede hacer el usuario (editar cantidad, editar precio, elegir, confirmar…).
- **Referencia:** dónde ya existe algo parecido en la app, cuando aplica.
- **Estados:** vacío, error, avisos y validaciones visibles.

## Cambios a UI existente

### <Pantalla o sección existente>

- **Cambia:** qué se agrega, quita o se comporta distinto.
